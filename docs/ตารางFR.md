## **สรุปและวิจารณ์ผล**

**ปัญหาที่พบระหว่างออกแบบและติดตั้ง**

1.ไม่แน่ใจว่าช่างกับหัวหน้างานควรเป็นคลาสแยกหรือเป็นบทบาทของ User

**วิธีที่แก้ไข**

แก้: ให้เป็น role ของ User เพราะข้อมูลเหมือนกัน ต่างกันที่สิทธิ์ แล้วแยกสิทธิ์ที่ Use Case

**จุดแข็งและจุดที่ควรปรับปรุงของผัง UML และโครงสร้างโปรเจกต์**

**จุดแข็ง:**ทุก FR มี Use Case รองรับ และทุก Use Case ใช้ Class อย่างน้อย 1 คลาส ตรวจย้อนกลับได้ 

**จุดที่ควรปรับปรุง:**สถานะเป็นข้อความธรรมดา ควรแยกเป็น enum หรือวาด State Diagram ว่าเปลี่ยนจากสถานะไหนไปไหนได้
